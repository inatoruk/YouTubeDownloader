# ダウンロードの流れ

1. main.pyが起動環境・ログ・診断を準備し、qt_app.pyのQt画面を開きます。
2. URLパネルから単一・一括URLを入力します。プレイリストはキュー管理側で展開し、チャンネル一覧はURLパネルのワーカーが取得します。
3. queue_manager.pyが各項目にIDと状態を付け、動画情報の取得を進めます。
4. ユーザーが形式と保存先を決めて開始します。既定のダウンロード同時数は2です。取得待ちの項目も情報がそろった後に処理します。
5. ワーカーがdownloader.pyを通じてyt-dlpを呼び、必要に応じてFFmpegが動画・音声を結合・変換します。
6. 完成ファイルの実パスを確認し、同名があれば連番を排他的に確保して保存します。
7. QtのSignalで状態と進捗が画面へ戻り、一覧展開を含むすべての作業が終わると結果が表示されます。

Pythonの画面イベントを止めないよう、情報取得やダウンロードはワーカースレッドで処理します。進捗は複数ストリームをまとめた表示なので、単なる経過時間の割合ではありません。

一時エラーは最大3回まで試行します。恒久的と分類したエラーやキャンセルは無駄な再試行を避けます。停止はワーカーのキャンセルフラグと進捗通知で伝わるため、通信状態によって反映に時間がかかる場合があります。

保存先の初期値はDownloads。ログは `~/Library/Logs/YoutubeDownloader/` です。ソース版のyt-dlp更新はpip経由、.app版は再ビルドで反映します。

[実装の詳細](download_mechanism_precise.md) / [操作ガイド](../user/USER_MANUAL.md)

終了時は全種類のワーカーに中断を要求し、GUIタイマーで安全な終了を待ちます。強制的なスレッド終了は行いません。
