# テストと検証

## 自動テスト

プロジェクトのトップで実行します。YouTube通信、アプリ更新・インストールは行いません。

```sh
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s scripts -p 'test_*.py' -v
QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/smoke_check.py
```

- `test_download_cleanup.py`: 失敗・中断・変換後中断の清掃、既存ファイル保護、成功時の連番保存。
- `test_download_safety.py`: 並列保存、移動失敗、後処理後パス、不正な完成形式、中断、URL検証。
- `test_media_conversion.py`: ローカルWebMを実際のyt-dlp/FFmpegでMP4・MP3・WAVへ変換し、ffprobeで確認。FFmpeg/ffprobe未導入時はスキップ。
- `test_app_regressions.py`: 入力経路、プレイリスト展開待ち・失敗・クリア・停止、チャンネル確認後の再検証と旧結果破棄、再試行表示、描画タイマー、保存先、全種類のワーカー終了待ち。
- `test_queue_worker_lifecycle.py`: 結果通知後、スレッド終了前に破棄・次の取得を開始しないこと。
- `test_update_and_install.py`: コピー・署名検証をスタブ化したインストール復旧テスト。
- `smoke_check.py`: GUI構築と既存の単一・一括・直接開始・チャンネル取得・停止経路。

## Qt環境の切り分け

`Incompatible processor ... neon`は今回のサンドボックス内で発生し、サンドボックス外でQtCoreのテストは成功しました。環境由来の異常終了をテスト成功・スキップ扱いにしません。

この環境ではQtプラグインの`hidden`属性によりoffscreenプラグインを発見できませんでした。既存の依存環境を変更せず、`libqoffscreen.dylib`を一時フォルダへコピーしてコピー側のみ`chflags nohidden`を適用し、`QT_QPA_PLATFORM_PLUGIN_PATH`をそのフォルダへ指定することでGUIテストを実行しました。通常の環境ではこの対処は不要です。

## 手動で確認する項目

- 実際のYouTubeで動画・プレイリスト・チャンネル、各画質、MP3各ビットレート、WAVを確認する。
- 通信・変換中の停止では「停止処理中」が表示され、終了後も自動再開しないこと。
- 情報取得・一覧取得・変換・更新中に閉じると、操作を無効にして待機し、安全に閉じること。
- 同名の別動画を保存し、双方が残ること。
- 保存先・形式が実行中は変更できず、完了画面が実際の保存先を開くこと。
- `.app`版では署名・起動・外部ツールの検出・通信を別途確認する。

今回のソース修正では実際のYouTube通信、`.app`の再ビルド・配置は対象外です。オフラインQtテストやローカル変換の成功と、実サイト・配布版の検証は区別します。

### UI品質調整・独立レビュー

macOS標準フォントを解決して使用し、カスタム省略ラベルも明示的に同じフォントと文字アンチエイリアスを使用。入力欄と追加ボタンの枠を統合、保存先を名前と短縮パスに整理、コンボの矢印を明確化し、実サムネイルに角丸クリップを追加した。背景のグラデーションはDPRに合わせて生成し、RGB共通の1階調未満の確率丸めでバンディングを低減する。右側の作業面は単色。背景画像はキャッシュし、2xサイドバー生成はこの環境で約28msだった。

別エージェントによる独立画像レビューを挟んで調整。Qtの2xオフスクリーン画像でライト／ダークを評価し、全32件の回帰テストが成功。サムネイルの角が透明で中央が不透明になることも確認した。実ディスプレイの色管理・見え方との完全一致はこの検証の対象外。
