# YouTubeダウンロード仕組みの詳細解説

このドキュメントでは、YouTube Downloader がどのようにして動画をダウンロードするのか、内部の仕組みを初心者向けに1つずつ丁寧に説明します。技術用語はなるべく避け、図解と例え話を使います。

## 1. 全体の流れ（ユーザー視点）

```
ユーザー操作             内部処理（見えない部分）
┌─────────────┐
│ URL入力      │
└──────┬──────┘
       │
┌──────▼──────┐
│ ボタンをクリック       │
└──────┬──────┘
       │
       ├─→ バリデーション（URL正しい？）
       │
       ├─→ yt-dlpに指示（YouTube動画取得）
       │
       ├─→ ダウンロード開始
       │
       ├─→ 進捗表示（プログレスバー更新）
       │
       ├─→ 完了またはエラー
       │
┌──────▼──────┐
│ ダイアログ表示  │
│（完了/失敗）  │
└──────────────┘
```

- **ユーザーが見る部分**: URL入力フォーム、ボタン、プログレスバー、ステータスメッセージ、完了ダイアログ。
- **ユーザーが見えない部分**: バックグラウンドで動く処理（ダウンロード、ログ記録、エラー検知）。

---

## 2. 主要な4つのコンポーネント（部品）

### 2.1 gui.py（GUI・画面表示）
**役割**: ユーザーが操作するウィンドウ（入力フォーム、ボタン、プログレスバー）を管理。

**具体的にやること**:
- URL入力フィールド、フォーマット選択（MP4/MP3）、解像度ドロップダウン、保存先ボタンを表示。
- 「ダウンロード」ボタンをクリックすると `downloader.py` の関数を呼び出す（ただしバックグラウンドで）。
- ダウンロード中の進捗情報（例: "50% 完了"）を受け取って、プログレスバーに反映。
- 完了またはエラーをダイアログで通知。

**例え話**: gui.py は「ユーザーと機械の窓口」。ユーザーが入力したURLや設定を受け取り、処理チームに指示を出し、結果をユーザーに返す。

### 2.2 downloader.py（ダウンロード処理の中核）
**役割**: yt-dlp（YouTube動画取得ツール）を操作し、実際のダウンロードを制御。

**具体的にやること**:
- YouTubeサイトにアクセスして動画情報（タイトル、長さ、解像度など）を取得。
- ユーザーが指定した解像度（720p/1080p/1440p/2160p/4320p）に最適な動画・音声ファイルを自動選択。
- 動画と音声を統合（FFmpeg利用）し、動画はMP4、音声はMP3として出力。
- ダウンロード途中の進捗（「10MB取得」など）を記録し、gui.py に伝える。
- 失敗時（ネットワークエラー、FFmpeg未導入など）は詳細エラーメッセージを出力。
- 自動更新（`yt-dlp -U`）で最新版ツールに保つ。

**例え話**: downloader.py は「配達人」。YouTubeサイトまで行って動画を持ってきて、形式を整えて、進捗を報告する。失敗したらその理由を返す。

### 2.3 utils/logging_config.py（ログ記録）
**役割**: アプリのあらゆるイベント（起動、ダウンロード開始、完了、エラーなど）をファイルに記録。

**具体的にやること**:
- ログメッセージ（例: "2025-11-10 09:15:32 [INFO] youtube_downloader: Download started: https://..."）を生成。
- ファイル `~/Library/Logs/YoutubeDownloader/app.log` に追記。
- ファイルサイズが1MBを超えたら古いログをバックアップ（app.log.1など）に移し、新規app.logを開始（ローテーション）。最大5世代保持。
- デバッグ時にエラー原因を特定するのに重要。

**例え話**: logging_config.py は「記者」。起きたことすべてを記録ノートに書き込み、ノートが満杯になったら新しいノートに切り替える。

### 2.4 main.py（エントリーポイント）
**役割**: アプリ全体の起動地点。各部品を初期化してGUIループを開始。

**具体的にやること**:
- ログシステムを初期化（logging_config.py を呼び出し）。
- GUIを起動（gui.py を呼び出し）。
- アプリが閉じるまでループ。

**例え話**: main.py は「プロジェクトマネージャー」。朝出社したとき、まずログシステムをセットアップして、スタッフに仕事を指示してから1日が始まる。

## 3. ダウンロード処理のステップバイステップ

### ステップ 1: ユーザーが URL を入力してボタンをクリック
```
GUIフォーム:
┌──────────────────────────────┐
│ YouTube URL                   │
│ https://youtube.com/watch?... │
├──────────────────────────────┤
│ ○ 動画 (MP4) ◉ 音声 (MP3)    │
├──────────────────────────────┤
│ 解像度: [720p ▼]              │
├──────────────────────────────┤
│ 保存先: /Users/jun/Downloads  │
├──────────────────────────────┤
│ [ダウンロード]  [閉じる]       │
└──────────────────────────────┘
```
gui.py の「ダウンロード」ボタンクリックイベントが発火。

### ステップ 2: URL バリデーション（入力チェック）
**実行ファイル**: gui.py の `_on_start_download()`

```python
# 疑似コード
if url 未入力:
    → エラーダイアログ「URLを入力してください」
    → 処理終了
if url が "http" で始まらない:
    → エラーダイアログ「有効なYouTube URLを入力してください」
    → 処理終了

# OKならダウンロード処理へ
```

**例え話**: 配達員が荷物を受け取る前に、住所が正しいか確認するようなもの。不正な住所なら受け取らない。

### ステップ 3: バックグラウンドスレッドでダウンロード開始
**実行ファイル**: gui.py + downloader.py

```
メインスレッド（GUI）          ワーカースレッド（ダウンロード）
    ↓
[ダウンロード]ボタンクリック
    ↓
┌─ ボタン無効化（連続クリック防止）
│  進捗: 0%
│  ステータス: "ダウンロードを開始します..."
│
│  ワーカースレッド起動 ──→ Downloader.download() 実行
│                             ├─ yt-dlp に指示
│                             ├─ YouTube からデータ取得
│                             ├─ ファイル生成
│                             └─ イベントキューにデータ送信
│
│  ← イベントキュー（Queue）経由で進捗受信
│  キューから「進捗 25%」取得
│  プログレスバー更新 → 25% 表示
│  
│  ← イベントキュー「完了」受信
│  プログレスバー 100%
│  ボタン有効化
│  ダイアログ表示「保存先: /Users/.../video.mp4」
```

**なぜスレッド分離？**  
ダウンロードは時間がかかる（動画サイズによっては数十秒～分単位）。メインスレッドのままだとGUIが固まる。バックグラウンドスレッドで実行 → GUIは常にレスポンシブ（あなたの要件: 快適な動作）。

### ステップ 4: yt-dlp（YouTube ダウンロードツール）の処理
**実行ファイル**: downloader.py の `download()`

```
yt-dlp がやること:
1. YouTube にアクセス
   ├─ ビデオID解析
   ├─ 利用可能な解像度/音声リスト取得
   └─ タイトル、長さ等の情報取得

2. ユーザー指定の解像度でファイル決定
   例: 720p 選択
   → 720p 以下の最高品質を自動選択
   → 動画（MP4）と音声（MP3）を個別ダウンロード

3. ファイルマージ（FFmpeg 使用）
   動画ファイル + 音声ファイル → 統合MP4
   または
   音声のみ抽出 → MP3

4. ダウンロード進捗を記録
   → gui.py に progress_hook（コールバック）で通知
   進度データ例:
   {
     'status': 'downloading',
     'downloaded_bytes': 52428800,  # 50MB
     'total_bytes': 209715200,       # 200MB
     'eta': 30                       # 残り30秒
   }
```

**進捗フック（progress_hook）の仕組み**:
```python
# downloader.py
def _progress_hook(self, data):
    percent = (data['downloaded_bytes'] / data['total_bytes']) * 100
    # キューに送信 → gui.py が受け取り → プログレスバー更新
    self._event_queue.put({'type': 'progress', 'progress': percent})
```

**例え話**: ダウンロードは「配達」。進捗フックは「配達员が『現在50%進みました』と随時連絡してくれるシステム」。

### ステップ 5: 完了またはエラー処理
**実行ファイル**: gui.py の `_handle_event()`

#### 完了時:

イベント: {'type': 'complete'}

## 4. 進捗表示の仕組み（スレッド間通信）

GUI が固まらないようにするため、**キュー（Queue）** という仕組みを使ってスレッド間通信をしています。

```
ワーカースレッド（ダウンロード）
    │
    ├─ 10% 進捗 → キューに入れる
    │            queue.put({'type': 'progress', 'progress': 10})
    │
    ├─ 50% 進捗 → キューに入れる
    │
    └─ 100% 完了 → キューに入れる
            queue.put({'type': 'complete'})

メインスレッド（GUI）
    │
    ├─ 100ms ごとに「キューに何か入ってない？」チェック
    │   ├─ 「進捗 10%」取得 → プログレスバー更新
    │   ├─ 「進捗 50%」取得 → プログレスバー更新
    │   └─ 「完了」取得 → ダイアログ表示
    │
    └─ GUI操作可能（ユーザーはいつでもクリック可能）
```

**なぜキューが必要？**  
スレッドが直接GUI変数に書き込むとバグ（競合条件）が生じる。キューを使うことで、メインスレッドが安全に受け取って処理できる。

## 5. エラーハンドリングの詳細

### 5.1 FFmpeg 未導入
```
downloader.py → yt-dlp 呼び出し
                    ↓
                FFmpeg 必要だけど見つからない
                    ↓
                DownloadError 発生
                    ↓
              イベントキューに送信
                    ↓
              gui.py がダイアログ表示
                    ↓
            ユーザーに通知: "FFmpeg is not installed"
            ログに記録
```

**対策**: README に `brew install ffmpeg` を記載。

### 5.2 ネットワーク切断
```
downloader.py → YouTube に接続試行
                    ↓
                接続失敗（タイムアウト）
                    ↓
                リトライ（最大3回）
                    ↓
                全リトライ失敗
                    ↓
          DownloadError（詳細メッセージ付き）
                    ↓
              ユーザーに「ネットワークエラー」通知
```

### 5.3 保存先の権限不足
```
downloader.py → ファイルを保存先に書き込み
                    ↓
            「Permission denied」エラー
                    ↓
            エラーメッセージ生成
                    ↓
          gui.py に通知 → ダイアログ表示
```

## 7. 自動更新（yt-dlp -U）の仕組み

```
main.py 起動
    ↓
logging_config.py 初期化
    ↓
gui.py（Application）作成
    ↓
downloader.py の __init__ 呼び出し
    ↓
"Downloader._ensure_updated()" 実行
    │
    ├─ yt-dlp -U をバックグラウンド実行
    │  （新しいバージョンあるか確認 → インストール）
    │
    └─ 結果をログに記録
       ├─ 成功: "[INFO] yt-dlp update complete"
       └─ 失敗: "[WARNING] yt-dlp update failed: ..."
    
GUI 表示（ユーザーは気付かない）
```

**なぜ自動更新？**  
yt-dlp は YouTube の変更に対応するため頻繁に更新されます。古いバージョンだとダウンロード失敗の可能性があるため。

## まとめ

| 部品 | 役割 | 例え |
|-----|------|------|
| `gui.py` | ユーザーインターフェース | 店員（ユーザー対応） |
| `downloader.py` | ダウンロード実行 | 配達員（YouTube から持ってくる） |
| `utils/logging_config.py` | ログ記録 | 記者（イベント記録） |
| `main.py` | 全体起動 | マネージャー（朝出社時に各部署指示） |

**全体の流れ（最小化版）**:
1. ユーザーが URL を入力
2. GUI がバックグラウンドで downloader.py を実行
3. downloader.py が yt-dlp でダウンロード（進捗を Queue で通知）
4. GUI がプログレスバー更新
5. 完了またはエラー通知
6. ログに記録

このシンプルな仕組みで、快適で保守しやすいダウンロードアプリが成立しています。
